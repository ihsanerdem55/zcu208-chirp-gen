# Branch review and 4x interpolation — 1 October 2026

Reviewed base: `cad5a90` (branch `codex/band-limited-noise`, which adds the
band-limited noise mode). This round reviews that branch and moves the RF-DAC
from 8x to 4x interpolation to double the usable bandwidth.

## Readiness

RTL simulation, Tcl and Python tests only. The 4x build has **not** been
through Vivado IP validation, implementation or a board measurement. Rebuild
from these sources; `.bit`/`.ltx` files from the 8x build do not match the new
RFDC configuration or the 256-bit stream.

## 4x interpolation

| | 8x (before) | 4x (now) |
|---|---|---|
| RFDC input rate | 737.28 MSPS complex | **1474.56 MSPS complex** |
| Usable band around the NCO (±0.4·fs_bb) | ±295 MHz | **±590 MHz (~1.18 GHz)** |
| Samples per 184.32 MHz fabric clock | 4 | 8 |
| AXI4-Stream | 128 bits, 8 words | 256 bits, 16 words |
| Fabric clock, CDC constraints, MMCM supervision | 184.32 MHz | unchanged |
| Pulse timing resolution (PW, PRI) | 5.425 ns | unchanged |
| FSTART resolution | 0.17 Hz | 0.34 Hz |
| KRATE resolution / maximum slope | 0.49 MHz/s / 1.06 GHz/µs | 1.98 MHz/s / 4.25 GHz/µs |
| Sin/cos ROMs, amplitude DSPs | 4 dual-port ROMs, 8 DSP | 8 dual-port ROMs, 16 DSP |
| ILA | 128-bit stream + 8 lane probes | 256-bit stream + 16 lane probes |

The fabric clock stays at 184.32 MHz (5898.24 MSPS / 4 × 2 words / 16 words),
so the clocking, reset supervision and CDC constraints are unchanged. Doubling
the lanes at the same clock was preferred over a 368.64 MHz fabric clock: the
8x build met timing with +0.98 ns of slack at 184.32 MHz, which a doubled
clock would not leave.

`chirp_core` is now written for any lane count (2 to 16). Every lane offset
T_m = m·f + K·m(m−1)/2 is its own accumulator, so each recurrence remains a
single 2-operand 48-bit add behind the start mux, as in the 4-lane timing fix.
The start values and increments are shift-add products of the quasi-static
parameters (signed-digit, at most three terms, no DSP), registered in two
stages. `tcl/build_bd.tcl` sets `DAC_Interpolation_Mode00 4` and
`DAC_Data_Width00 16`, and fails unless the RFDC stream is 32 bytes and the
fabric clock 184.32 MHz. `chirp_ctrl.tcl` uses INTERP = 4 and LANES = 8 and
refuses to drive a DAC that reads back another interpolation factor.

## Findings and changes

| Priority | Finding | Change |
|---|---|---|
| High | `noise_mode` (CTRL[4]) was missing from the bundled-parameter `set_max_delay`/`set_bus_skew` lists in `chirp_timing.xdc`. Its AXI→DAC crossing was timed as an ordinary path between unrelated clocks. | Added to the destination regexp. |
| High (timing) | `noise_src` did four serial 35-bit adds, a 4-deep held-value mux chain and a 0..4-step LFSR advance mux in one 5.4 ns cycle. No implementation run had covered it, and it could not scale to 8 lanes. | Lane m now uses n_m = ⌊(nacc + (m+1)·ninc)/2³²⌋ with registered (m+1)·ninc: one add per lane, in parallel. The value is chosen directly (held value if n_m = 0, else draw n_m−1). The LFSRs advance a fixed LANES steps per clock, and unused draws are discarded. Two pipeline stages. In a Yosys LUT6 mapping the longest path fell from 14 to 7 levels, at twice the lanes. |
| Medium | "A capture is reproducible run to run" held only for the first noise command after reset: the LFSRs also advanced in chirp mode whenever KRATE was non-zero. | Every APPLY reseeds the generator, so the same command always gives the same samples. `noise -seed N` (PHASE0, unused in noise mode) selects another realisation. |
| Medium | Reloading a running output (APPLY without `gen_off`) changed amplitude, I/Q swap, packing and noise select at once for the samples already in the pipeline. A load that coincided with a pulse start used the new start phase with the old start values. The Tcl commands always disable first, so only direct register use was affected. | These controls now travel down the pipeline with the gate, and P0 is delayed like the start values. The old waveform finishes unchanged and exactly one zero block separates old and new. |
| Low | `plot_ila.py` took one FFT after subtracting the mean. That carved a notch at 0 MHz and gave a ±10 dB scatter on noise. | Welch average (Hann, 50 % overlap). `--lanes` and `--fs-bb` default to the 4x build. |
| Low | The commands could not tell when the RF band (NCO ± baseband) folds below 0 Hz or crosses FS_DAC/2, which matters more with a 1.18 GHz band. | `nco_set` records the NCO; `cw`, `chirp` and `noise` warn on either crossing. |
| Test | The noise checks were statistical only. The chirp scoreboard could not follow back-to-back pulses (PW = PRI), and no test reloaded a running output. | Bit-exact sequential noise model for every gated sample. Fractional-hold, seed and reload-reproducibility tests. Chirp tests for PW = PRI, PW 1 / PRI 2 and four reloads while running. A noise spectrum check against sinc² in `analyze.py`. |

## Validation performed

- Icarus Verilog 12 and Verilator 5.020: the chirp testbench checks
  **94,944 samples with zero mismatches**. That includes 1 GHz up-chirps, a
  600 MHz down-chirp, CW at ±550 MHz, both packings, I/Q swap, the timer
  corner cases and reloads while running.
- The noise testbench compares **148,184 gated samples against a sequential
  per-sample model with zero mismatches**, and checks D = 1, 16 and 2.5 hold
  lengths, amplitude scaling, pulse gating, reproducibility across reset and
  reloads, and seed selection.
- `analyze.py` passes 14/14 checks: CW SFDR 84.4 dBc; the 1 GHz chirp is
  bit-exact with a frequency error within the 14-bit phase quantisation
  (±90 kHz); the 200 MHz noise band follows sinc² within 1.2 dB in band, with
  its −3 dB width 1.00 × bw and nulls at ±bw below −23 dB.
- Mutation checks. Each of the following fails a testbench:
  - chirp: dropping the second restart clock, the gate-aligned
    amplitude/packing, or the delayed P0; a wrong lane increment; a wrong
    triangular term;
  - noise: a draw-index off by one, the held value taken from the wrong lane,
    a wrong (m+1)·ninc constant, no reseed, a wrong LFSR advance, or an
    ignored seed.
- Register regression, Tcl tests with mocked AXI/RFDC read-back (4x, 16 words)
  and ILA CSV tests (10/10) pass. Verilator `-Wall` lint now reports only
  unused bits (address, TREADY, product, LFSR slice and per-lane sum bits) and
  the known `dac_rst_n` sync/async note; the noise slice width warnings are gone.

## Before the first 4x RF measurement

1. Build with `tcl/build_bd.tcl` and open the RFDC GUI: 4x interpolation,
   16 samples (words) per AXI4-Stream cycle, 256-bit `s00_axis`, 184.32 MHz
   fabric clock, fine mixer, full-bandwidth datapath. If the IP refuses the
   combination, stop: do not change the fabric clock without revisiting the
   design.
2. Implementation: check `report_timing_summary` in the DAC domain. The
   datapath is twice as wide; record the WNS and compare with the +0.98 ns
   of the 8x build. Check that the `noise_mode` path is now covered by the
   max-delay and bus-skew exceptions in `report_cdc`/`report_bus_skew`.
3. `rfdc_status` must show interpolation 4x, and the fabric-word read-back
   should be 16. Record it.
4. Start at `-amp 0.1`. A wideband signal near full scale can overshoot in the
   RFDC interpolation filters, so raise the amplitude in steps while watching
   the spectrum.
5. A 1 GHz band does not fit the ~10 MHz–1 GHz balun path used for the 500 MHz
   examples. Choose the NCO and output path together (the commands warn about
   0 Hz and Nyquist crossings, not about the balun).
