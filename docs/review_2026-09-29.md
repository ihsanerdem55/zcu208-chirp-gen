## Findings and changes

| Priority | Finding | Change |
|---|---|---|
| High | DAC-only reset cleared the receiver's toggle history. With an odd old APPLY toggle, the receiver replayed the old enabled settings on recovery. Even toggles behaved differently. | Synchronize/baseline the existing toggle during recovery without loading it. Keep the generator disabled until a fresh APPLY. STATUS bit 0 now means the handshake is ready, after this recovery interval. |
| High | All AXI/DAC paths were cut with `set_clock_groups`. The multi-bit parameter bus had no physical delay/skew bound relative to its synchronized request. | Bound parameter delay and skew to 5.425 ns; false-path only the first stage of each single-bit synchronizer. Keep synchronizer interstage paths timed. Constraints fail if the expected cells cannot be found. |
| Medium | A second APPLY could cancel a pending request; parameter writes could change data while the DAC clock was stopped. Protection existed only in the Tcl helpers. APPLY also ignored zero WSTRB. | Reject conflicting writes with AXI SLVERR, preserve pending parameters, and treat zero-strobe writes as no-ops. |
| Medium | `gen_off` required an already-running RFDC. Restarting a live tile could retain an enabled waveform. | Allow disabling with a live/ready generator domain even if the RFDC is unhealthy. Silence before and after a tile restart. Enabling still requires RFDC readiness. |
| Medium | AXI clock/reset loss did not explicitly reset DAC-side state. | Connect the AXI reset controller's active-high peripheral reset to the DAC reset controller's auxiliary input; specify reset polarities explicitly. |
| Test | The original testbench drove AXI and reset on sampling edges, producing simulator-dependent races. | Drive on falling edges and check write responses; add separate CDC/AXI recovery regressions. |

A reset aborts any in-flight APPLY. Reissue the desired waveform only after
STATUS bit 0 returns and bit 1 clears. A frozen clock without reset cannot
acknowledge `gen_off`; a timeout is **not** confirmation of silence. Restore
clocks/reset or reprogram before continuing. These controls are not an analog
emergency shutdown mechanism.

## Follow-up bring-up review

Reviewed base: `2f707a4`. Board pins (AP20/AP19 = 300 MHz `USER_SI570_C0`,
AU1 = `CPU_RESET`, AR19 = LED0) were re-checked against the production board
files. The RFDC offsets and masks in `chirp_ctrl.tcl` (tile/DRP bases, state,
status, restart, NCO word and immediate update) were re-checked against the AMD
`rfdc` driver sources. All matched.

| Priority | Finding | Change |
|---|---|---|
| High | `clk_wiz_dac` had no reset input. Its input `rfdc/clk_dac0` is absent at configuration and stops during every tile restart, and an MMCM must be reset after LOCKED falls. A late CLK104 profile or `rfdc_restart` could leave the DAC fabric clock, ILA clock and heartbeat dead until the FPGA was reprogrammed. `rfdc_restart` also had to refuse to run once the fabric clock was gone, because an enabled waveform frozen in the stopped domain could resume. | The AXI-clocked register block supervises the MMCM. While it is unlocked, a 160 ns reset is pulsed every 2.6 ms. The DAC reset controller (`rst_dac/aux_reset_in`, which also takes the AXI reset) is held until lock has been stable for 1.28 µs. Every clock loss therefore ends with a DAC-domain reset, and the generator returns disabled. STATUS bit 3 reports MMCM lock. |
| High | `run_hw_axi -quiet` returns TCL_OK even when a transaction fails. AXI timeouts, a lost JTAG link and the RTL's SLVERR rejections were invisible, and reads could return stale data. | `-quiet` is removed. Failures raise an error naming the address, and read data is validated. Only the per-read `READ DATA` info message is suppressed. |
| Medium | The frequency math assumes 8x interpolation, I/Q input and a full-bandwidth datapath. The driver halves the NCO rate in IMR mode. Nothing checked any of this on silicon. | `rfdc_status` reads back interpolation, I/Q input, datapath mode and fabric words. `cw`, `chirp` and `nco_set` refuse to run on a mismatch; `set ::RFDC_CONFIG_CHECK 0` overrides this for diagnosis only. |
| Medium | `chirp_wait_idle` failed on the first read during a DAC-domain recovery. `gen_off` failed while the domain was held in reset, even though reset already forces the generator off. | The handshake wait now lasts up to `::WAIT_MS`. `gen_off` treats STATUS[0] = 0 as off and clears the staged enable. A live handshake that never acknowledges still fails. |
| Low | `debug_hub.tcl` depended only on a BD net name that synthesis may rename. | It falls back to the net on `clk_wiz_axi/clk_out1`. |
| Low | One `ASYNC_REG` attribute covered three synchronizer declarations. | Split into one attribute per declaration. |

Validation of this follow-up:

- Icarus Verilog 12 and Verilator 5.020 both pass: 48,840 waveform samples
  with zero mismatches, plus the register regression, which now covers MMCM
  reset retry period/width, lock status, a stable-lock hold, re-reset on lock
  loss and the AXI-reset path.
- Mutation checks: removing the MMCM reset retry, the stable-lock hold or the
  STATUS lock bit each fails `tb_chirp_regs`. Restoring `run_hw_axi -quiet`
  fails `test_ctrl.tcl`.
- Python analysis 10/10, ILA CSV tests 6/6, and Tcl tests with mocked AXI and
  RFDC read-back all pass.
- Verilator lint reports no new warnings. The existing ones are intentional:
  unused address/TREADY/product bits, and `dac_rst_n` used as an asynchronous
  reset in the register block but a synchronous one in the core. That is safe
  because `proc_sys_reset` drives it synchronously to `dac_clk`.
- Still not performed: Vivado IP validation, synthesis, implementation and
  board measurements.

## Before the first RF measurement

1. Build a fresh project with `tcl/build_bd.tcl`. Validate the BD and verify the
   RFDC GUI: tile 228/channel 0, local PLL, 245.76 MHz reference, 5.89824 GSPS,
   8x interpolation, fine I/Q-to-real mixer, 128-bit input, 184.32 MHz fabric.
   Confirm the normal datapath/IMR bypass used by the NCO frequency calculation.
   Confirm `clk_wiz_dac/reset` is driven by `chirp_gen_0/dac_mmcm_reset` and
   `rst_dac/aux_reset_in` by `chirp_gen_0/dac_domain_reset`.
2. Complete implementation. Inspect DRC, `report_timing_summary`, `report_cdc`,
   `report_bus_skew`, and `report_methodology`. Resolve violations, missing or
   overridden CDC constraints, and unconstrained internal paths before use.
   The scope-marker output and asynchronous reset input are intentionally exempt,
   as are the first stages of `lock_sync` (MMCM LOCKED) and the other synchronizers.
   Check that the `dac_domain_reset` path into `rst_dac` is covered by the
   reset IP's own synchronizer constraints.
3. Confirm the board revision, normal cooling, and actual CLK104 profile/output:
   LMK DCLKout6 at 245.76 MHz. The repository does not program CLK104.
4. Program matching `.bit` and `.ltx`. Run `hw_init`, `rfdc_status`, and
   `clock_check`. Require running state 15, power-up/PLL-lock set, MMCM locked,
   handshake ready, and changing heartbeat. The read-back must show interpolation
   8x, I/Q input 1 and datapath mode 0. Record the reported fabric-word count:
   it has not yet been checked on silicon. If recovery is needed,
   `rfdc_restart` leaves output off.
5. Use the intended XM655/balun output and a correctly rated 50-ohm measurement
   path. Verify instrument input limits and attenuation before connecting RF;
   the digital amplitude setting is not a calibrated output-power value.
6. Start with `nco_set 500e6; cw 10e6 0.1`, check the expected ~510 MHz tone,
   then try the chirp at `-amp 0.1`. Check ILA lanes and zeros between pulses,
   and measure the analog spectrum separately. Finish with `gen_off`.
7. Exercise recovery once without reprogramming: with a tone on, run
   `rfdc_restart`. Expect output off, MMCM locked again, `clock_check` passing,
   and a working `cw` afterwards.

## Cross-checks against AMD sources

- [Production ZCU208 board pins](https://github.com/Xilinx/XilinxBoardStore/blob/2022.2/boards/Xilinx/zcu208/production/2.0/part0_pins.xml):
  AP20/AP19, AU1 and AR19 match this project's XDC.
- [RF-DAC interface format, PG269](https://docs.amd.com/r/en-US/pg269-rf-data-converter/Interface-Data-Formats):
  I/Q is interleaved, even words I and odd words Q. TVALID does not gate DAC data;
  this RFDC-specific source intentionally emits every clock and sends zeros off-pulse.
- [AMD RFDC driver](https://github.com/Xilinx/embeddedsw/blob/master/XilinxProcessorIPLib/drivers/rfdc/src/xrfdc_mixer.c):
  NCO word writes and immediate update match the driver's register sequence for
  this single-channel normal datapath. This does not validate an actual NCO change.
- [AMD handshake CDC constraint example](https://docs.amd.com/r/2024.2-English/ug903-vivado-using-constraints/set_bus_skew-Example-One):
  bundled-data handshakes need a bounded data path in addition to control synchronization.
- [AMD MMCM primitive, UG974](https://docs.amd.com/r/2022.2-English/ug974-vivado-ultrascale-libraries/MMCME3_ADV):
  LOCKED is deasserted if the input clock stops, and the MMCM must be reset after
  LOCKED is deasserted.
- [AMD RFDC driver, xrfdc_dp.c](https://github.com/Xilinx/embeddedsw/blob/master/XilinxProcessorIPLib/drivers/rfdc/src/xrfdc_dp.c)
  and [xrfdc.c](https://github.com/Xilinx/embeddedsw/blob/master/XilinxProcessorIPLib/drivers/rfdc/src/xrfdc.c):
  Gen3 interpolation (DRP 0x040), I/Q input (0x044), datapath mode (0x034) and
  fabric write words (0x008) read-back used by `rfdc_status`.
