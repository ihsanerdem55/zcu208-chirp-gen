## Findings and changes

| Priority | Finding | Change |
|---|---|---|
| High | DAC-only reset cleared the receiver's toggle history. With an odd old APPLY toggle, the receiver replayed the old enabled settings on recovery. Even toggles behaved differently. | Synchronize/baseline the existing toggle during recovery without loading it. Keep the generator disabled until a fresh APPLY. STATUS bit 0 now means the handshake is ready, after this recovery interval. |
| High | All AXI/DAC paths were cut with `set_clock_groups`. The multi-bit parameter bus had no physical delay/skew bound relative to its synchronized request. | Bound parameter delay and skew to 5.425 ns; false-path only the first stage of each single-bit synchronizer. Keep synchronizer interstage paths timed. Constraints fail if the expected cells cannot be found. |
| Medium | A second APPLY could cancel a pending request; parameter writes could change data while the DAC clock was stopped. Protection existed only in the Tcl helpers. APPLY also ignored zero WSTRB. | Reject conflicting writes with AXI SLVERR, preserve pending parameters, and treat zero-strobe writes as no-ops. |
| Medium | `gen_off` required an already-running RFDC. Restarting a live tile could retain an enabled waveform. | Allow disabling with a live/ready generator domain even if the RFDC is unhealthy. Silence before and after a tile restart. Enabling still requires RFDC readiness. |
| Medium | AXI clock/reset loss did not explicitly reset DAC-side state. | Connect the AXI reset controller's active-high peripheral reset to the DAC reset controller's auxiliary input; specify reset polarities explicitly. |
| Test | The original testbench drove AXI and reset on sampling edges, producing simulator-dependent races. | Drive on falling edges and check write responses; add separate CDC/AXI recovery regressions. |

A reset aborts any in-flight APPLY. Reissue the desired waveform only after
STATUS bit 0 returns and bit 1 clears. A frozen clock without reset cannot
acknowledge `gen_off`; a timeout is **not** confirmation of silence. Restore
clocks/reset or reprogram before continuing. These controls are not an analog
emergency shutdown mechanism.

## Before the first RF measurement

1. Build a fresh project with `tcl/build_bd.tcl`. Validate the BD and verify the
   RFDC GUI: tile 228/channel 0, local PLL, 245.76 MHz reference, 5.89824 GSPS,
   8x interpolation, fine I/Q-to-real mixer, 128-bit input, 184.32 MHz fabric.
   Confirm the normal datapath/IMR bypass used by the NCO frequency calculation.
2. Complete implementation. Inspect DRC, `report_timing_summary`, `report_cdc`,
   `report_bus_skew`, and `report_methodology`. Resolve violations, missing or
   overridden CDC constraints, and unconstrained internal paths before use.
   The scope-marker output and asynchronous reset input are intentionally exempt.
3. Confirm the board revision, normal cooling, and actual CLK104 profile/output:
   LMK DCLKout6 at 245.76 MHz. The repository does not program CLK104.
4. Program matching `.bit` and `.ltx`. Run `hw_init`, `rfdc_status`, and
   `clock_check`. Require running state 15, power-up/PLL-lock set, handshake ready,
   and changing heartbeat. If recovery is needed, `rfdc_restart` leaves output off.
5. Use the intended XM655/balun output and a correctly rated 50-ohm measurement
   path. Verify instrument input limits and attenuation before connecting RF;
   the digital amplitude setting is not a calibrated output-power value.
6. Start with `nco_set 500e6; cw 10e6 0.1`, check the expected ~510 MHz tone,
   then try the chirp at `-amp 0.1`. Check ILA lanes and zeros between pulses,
   and measure the analog spectrum separately. Finish with `gen_off`.

## Cross-checks against AMD sources

- [Production ZCU208 board pins](https://github.com/Xilinx/XilinxBoardStore/blob/2022.2/boards/Xilinx/zcu208/production/2.0/part0_pins.xml):
  AP20/AP19, AU1 and AR19 match this project's XDC.
- [RF-DAC interface format, PG269](https://docs.amd.com/r/en-US/pg269-rf-data-converter/Interface-Data-Formats):
  I/Q is interleaved, even words I and odd words Q. TVALID does not gate DAC data;
  this RFDC-specific source intentionally emits every clock and sends zeros off-pulse.
- [AMD RFDC driver](https://github.com/Xilinx/embeddedsw/blob/master/XilinxProcessorIPLib/drivers/rfdc/src/xrfdc_mixer.c):
  NCO word writes and immediate update match the driver's register sequence for
  this single-channel normal datapath. This does not validate an actual NCO change.
- [AMD handshake CDC constraint example](https://docs.amd.com/r/2024.2-English/ug903-vivado-using-constraints/set_bus_skew-Example-One):
  bundled-data handshakes need a bounded data path in addition to control synchronization.
